# TELL 升级策略

更新基线：v0.5，2026-07-29

## 产品定位

TELL（中文名《破绽》）是面向全球市场的 AI 恐怖推理审讯游戏。核心不是自由聊天，而是阅读卷宗、交叉询问三名嫌疑人，并找出“只有凶手才会知道”的决定性破绽。

## 产品结构

- **TODAY'S CASE / 每日一案**：低负担回访、每日共同案件、同难度排名。
- **CASE RUN / 连续追凶**：通关后进入下一案，以连胜和挑战驱动长时游玩。
- 三档难度：见习探员、重案探长、黑档调查员；提问预算和提示量不同，成绩分榜。

## 推理与 AI 原则

- 案件卷宗、公开事实、时间线和开场证词是不可变事实。
- 模型只表演角色，不得替其他角色编造行动、关系、对话或不在卷宗中的不在场证明。
- 凶手可以隐瞒和撒谎，但不能改写世界；经过有效追问后才暴露关键知识破绽。
- 定罪必须同时选对嫌疑人和决定性证据，避免凭感觉猜人。
- 优先改进案件事实与提示约束，不依靠增加训练模型解决逻辑问题。

## 语言与品牌

- 统一使用全球英文图像字标 **TELL**，本地语言只作为副标题。
- 语言顺序：EN → ES → PT → 中文 → 日本語。
- “破绽”只出现在中文界面。
- 英文、中文是重点训练方向；西班牙语、巴西葡萄牙语和日语通过英文事实层进行运行时双向转换，不新增语料生产或独立训练模型。

## 视觉与声音

- 主菜单采用审讯室、案卷、血指纹、旧印刷和机密印章语言，避免普通 SaaS 界面与廉价万圣节风格。
- 每案三名嫌疑人使用不同肖像，人物外观随剧情和身份变化。
- 正文以可读性为先；恐怖字体只用于 Logo、案件标题、印章和关键结案信息。
- 原创四音 TELL 动机采用低沉、嘶哑、失谐、旧磁带与锈铁质感。
- 正式 BGM 使用 ACE-Step 1.5 预生成真实音频，不以浏览器振荡器充当音乐；菜单、审讯、逼近破绽、结案使用四条同源场景配乐并交叉淡化。
- 音乐在关键节点切换变体，审讯轨必须压在对白下方，依靠留白建立品牌记忆。
- 菜单主题与审讯配乐必须是独立音轨；进入卷宗后进行确定性交叉淡化，不允许菜单音乐继续覆盖审讯场景。
- v0.9 保留原创四音 TELL 动机，在既有 AI 母带上加入现代刑侦脉冲与工业打击层：菜单约 72 BPM、审讯约 92 BPM、逼近破绽约 116 BPM、结案约 68 BPM；节奏逐级加压但始终为对白留出频段。
- 音乐只借鉴生存恐怖与现代刑侦类型的节奏、留白和音色原则，不复刻任何现有游戏或影视作品的旋律、和声或录音。

## 推理服务

- TELL 审讯对话通过 Pop OS 的共享 Vulkan GPU 调度器提供；真实请求刷新租约，由调度器按实测显存预算将模型从 RAM 页缓存快速调入显存。
- 独立端口 `8809` 承载 Qwen 2.5 7B + TELL night1 LoRA。允许显存足够的双模型组合（TELL + Flutter 或 TELL + Mingxi），超过预算才把旧模型退回 CPU mmap，禁止绕过调度器独占显存。

## 商业与留存

- 每日模式负责习惯与回访，连续模式负责挑战、连胜和长时参与。
- 奖励围绕破案效率、连续破案、每日排名和案件档案成长设计。
- 评价入口使用“案卷评价”叙事包装，与整体美术统一。
- 先验证留存、完成率和案件质量，再扩展付费内容；不以堆语言模型扩大成本。

## 数据运营

- 漏斗：访问 → 模式/语言/难度 → 开案 → 阅读卷宗 → 审讯 → 提问 → 指控 → 破案 → 分享/下一案 → 评价。
- 统计维度：语言、模式、难度、案件、成功率、平均提问数、耗时、AI 延迟、失败率、评分和每日活跃。
- 运营面板：`/tell/analytics/dashboard`。
- 面板只显示聚合数据，不展示玩家 ID、审讯原文或评价文字。
- v0.5 之前没有完整维度的数据统一标为 `legacy`，不得错误归因。

## 可选侦探档案（v0.7）

- 登录永远可选；游客可完整开案、审讯、指控、结案和评价，不设置功能墙。
- 主菜单以“侦探档案”而非普通账号中心呈现，保持案卷叙事与恐怖侦探美术。
- 首发使用 Google Identity 登录；沿用同域已授权客户端，不新增密码存储。
- 匿名试玩记录通过 `account_pids` 关联到账号，不改写或丢弃历史数据；同一账号可聚合多设备破案记录。
- 会话使用 90 天 Secure、HttpOnly、SameSite=Lax Cookie；服务端只保存令牌哈希。
- 邮件 Magic Link 后端已实现一次性令牌、15 分钟失效和速率限制；只有配置邮件提供商和发件域名后，前端才显示入口。
- 登录完成、退出和邮件请求纳入漏斗事件；运营聚合不暴露邮箱或原始身份信息。

## 证据链推理（v0.8）

- **Social-MoE** 从单关键词开关升级为多信号语义路由，区分时间线、方法、物证、质证、动机、指控和他人行踪；未命中的自然问题仍进入角色回答，不直接判为“不知道”。
- **HSM-LCR** 按案件、当前嫌疑人、问题意图和证据阶段重排材料，避免某个秘密名词成为万能通关按钮。
- **RLS** 将公开证据、本人证词、本人秘密和他人信息分层；角色可隐瞒自己的行为，但不得为他人制造事实或改写时间线。
- **Titans** 不再只累计“有效问题次数”，改为持久化时间线是否建立、方法是否调查、物证是否提出、质证次数和破绽是否暴露。
- **BV-ToT** 对模型候选证词检查越权、无辜者泄密、凶手过早泄密和回答边界；不合格时按当前证据阶段回退，而不是统一回复“不知道”。
- 破绽释放条件变为“先建立本人时间线，再调查方法或物证，最后指出矛盾”；重复询问凶器、毒物或饮品不会触发答案。
- 卷宗移除“警方尚未公开”的明牌提示，改用中性物证；指控理由描述证词与物证的冲突，不直接复述秘密答案。
- 每名嫌疑人的完整问答记录在切换头像后恢复，并保持独立上下文。
- 审讯日志新增 `intent`、路由置信度、证据阶段、验证器、回退原因和检索层；运营面板显示规则回退率与成功质证次数。
- v0.8 仍冻结新增 LoRA；先让真实问题充分经过模型与验证器，再根据带标签日志决定是否微调语义路由或角色表达。

## 后续迭代守则

1. 先保证案件逻辑闭环，再增加内容数量。
2. 每个新案件必须有三条公开事实、三份开场证词、唯一关键破绽和两个合理干扰项。
3. 新功能必须接入漏斗事件并验证真实落库。
4. 保持统一 TELL 品牌、克制恐怖感和移动端可读性。
5. 不复制现有恐怖游戏的 Logo、音乐或美术资产，只借鉴成熟的节奏与信息层级原则。
